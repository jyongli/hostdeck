# HostDeck 设计与边界

2026-11-13，当前版本 1.3.0。用户接受独立 Chrome 窗口，同时最初希望能按同窗口标签选择 IP。

1.3.0 将 C# 桥和 Node 替换为同一个原生 EXE。一次性 Native Messaging 用于普通命令；只有登录导入才保留轻量子进程。子进程在导入完成后释放登录快照并等待 Chrome 退出。配置名继续使用规则排序后的 SHA256 前 12 位。发行副本压缩扩展文件，源码单独打包。

## 本次决定

用户实测当前标签切换会导致两个同域名网页同时退出。旧实现只隔离网络目标，仍共享 Chrome 配置中的 Cookie 和 localStorage；目标服务器拒绝原凭据后，网页清理共享存储就会影响另一标签。此前路由与共享 Cookie 的测试不足以证明登录隔离。本次真实浏览器回归使用两个认证服务复现了两边同时退出。

1.2.0 停用同窗口标签切换，删除持续 Fetch 拦截与旧调试事件处理，移除对应请求规则权限。后台保留旧 start 消息的拒绝入口，在任何导航前返回明确错误，避免旧界面或直接消息继续触发。不能以屏蔽 Invalid InterceptionId 提示冒充修好登录隔离。

当前交付为独立 Chrome 配置窗口、按网站导入登录、打开 Chrome 账户同步，以及免管理员注册和便携发行包。工具位于独立 browser-hostdeck 目录，不修改已有 Android 工程。环境 A/B 不推测测试和生产归属。

## 环境隔离

每个环境以独立 user-data-dir 和 host-resolver-rules 启动 Chrome，保持域名、Host 和 TLS SNI 校验。不同环境与规则版本使用不同配置目录，避免现有进程忽略新参数。直连环境不修改系统 hosts、DNS 或系统代理。相同环境复用配置，网站登录与 Chrome 账户同步由该配置保存。

两个环境的 Cookie 和 localStorage 不共用。服务器自身的单点登录策略或会话撤销逻辑仍可能影响登录，不能由浏览器配置隔离保证。

## 资料带入

仅用户主动点击带入登录时，扩展短暂连接当前网页的调试器，读取配置域名的适用 Cookie 与当前页的 localStorage / sessionStorage，随后立即解除；不导航源网页、不配置 Fetch、不读取全浏览器 Cookie 或 Chrome 密码库。

快照经域名、来源和大小校验后通过匿名管道送到独立 Chrome，在首个网站请求前设置 Cookie，并在页面脚本启动前一次性导入存储。存储脚本随后删除，不能持续覆盖环境内更新。Chrome 匿名调试管道断开会退出浏览器，因此轻量助手保留管道句柄并等待环境窗口关闭，不依赖源 Chrome 或扩展后台持续运行，不监听 TCP 端口。

Chrome 密码、书签及自动填充通过对应环境的 Chrome 原生同步设置，由用户登录 Google 账户。服务器不接受源凭据、设备绑定凭据、分区 Cookie 和 IndexedDB 等情况不保证登录迁移成功。

## 验收

- 旧标签切换必须在导航前失败，原两个网页的 Cookie、localStorage 和登录状态保持不变。
- 真实 Google Chrome 的两个独立配置分别连接两个认证服务、使用各自凭据登录；清理 B 的 Cookie 和 localStorage 后，A 与原 Chrome 均保持登录。
- 登录导入读取结束后解除临时调试，源网页地址和登录数据不变；目标脚本可读取导入值，后续刷新不覆盖更新。
- 没有读取用户密码、登录实际财务系统或执行业务写入；本地模拟不能替代目标系统验收。

升级 1.3.0 需重新注册本机助手，再重新加载扩展；不自动结束用户浏览器。

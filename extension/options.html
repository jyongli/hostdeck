环境管理

HostDeck · 为每个环境保存自己的解析规则

先选择一个环境，填写域名与目标 IP。不同环境分别在独立 Chrome 窗口中打开，各自保存网站登录。内置的 A/B 名称不代表测试或正式，请按实际用途修改。

登录隔离与账户资料

独立窗口适合日常测试、文件上传、实时功能和需要不同账号的场景。它使用独立 Chrome 配置，保持域名和 HTTPS 证书校验，并直连网络。依赖公司代理才能访问的网络可能无法直连。

需要原网站登录时，先关闭目标环境窗口，在原 Chrome 的已登录网页上选择「带入网站登录」。它复制该网站的 Cookie 及当前页 localStorage / sessionStorage，可能替换同名数据。服务器不接受原凭据、分区 Cookie 或登录依赖 IndexedDB 时仍需重新登录。Chrome 密码、书签和自动填充请点「同步 Chrome 资料」，在环境窗口登录原 Google 账户，由 Chrome 同步。

修改解析规则会打开新的隔离配置，以免旧进程继续使用旧 IP；旧窗口不会自动更改，请关闭不再使用的窗口。旧登录数据保留在本机。

当前标签切换已停用。同一 Chrome 配置中的同域名标签共享 Cookie 和 localStorage，一个环境清理登录会影响另一个。IP 分流不能提供登录隔离。升级前请先停止旧接管或关闭旧业务标签，之后对 HostDeck 点击重新加载。

独立窗口的浏览器存储互相隔离；若网站服务端本身限制同时登录或主动撤销凭据，仍可能要求重新登录，插件不能改变服务端规则。

「带入网站登录」会短暂显示 Chrome 调试提示，读取后立即解除，不持续拦截网络。完全退出 Chrome 后用工具目录的「隐藏调试提示启动Chrome.cmd」启动，可隐藏本次所有扩展的调试提示，并沿用原 Chrome 配置。

不修改系统 hosts、DNS 或代理，不安装证书、不关闭 HTTPS 校验。没有遥测或网页内容日志。只有主动复制的网站登录数据通过本机匿名管道交给随包助手；Chrome 账户同步由浏览器自身完成。
